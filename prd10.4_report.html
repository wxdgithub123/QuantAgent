一、完成结论

本次按需求文档完成 PRD 10.4 TradingAgents 决策层的全部开发工作。CoordinatorAgent 已从"各自查 ClickHouse 计算指标"的旧模式彻底重构为以 AnalysisContext 为唯一输入源的架构。系统现在具备四角色并行分析（技术/新闻/宏观/风控）、三段式多空辩论、结构化 AgentDecision 输出、coordination_history 持久化、以及 Ollama 本地 LLM 驱动的完整决策管线。

L5 AnalysisContext
  -> _load_analysis_context() (AnalysisContextBuilder)
  -> 4 角色并行分析 (asyncio.gather: technical / news / macro / risk)
  -> 风控否决检查
  -> 三段式多空辩论 (bull view / bear view / final judge)[fast_mode 可跳过]
  -> 加权投票 + 信号决策
  -> LLM 综合摘要
  -> _persist_result() -> coordination_history (全审计字段)
  -> CoordinationResult.to_dict() -> HTTP API 返回

三、多角色分析实现说明

角色1技术分析 (technical)

  • 输入：latest_factors（SMA/EMA/MACD/RSI/BOLL/ATR）、recent_signals（策略信号）、bars（最新 K 线 OHLCV）
  • LLM 任务：判断趋势方向与动量强度、超买超卖状态、均线排列及 MACD 交叉信号
  • 输出格式：OPINION / CONFIDENCE / RISK_FLAG / REASONING / KEY_POINTS
  • 解析：_parse_role_response() 正则提取各字段，映射 opinion 为 bullish/bearish/neutral

角色2新闻分析 (news)

  • 输入：news_events（标题、情绪分、标签、主题）
  • LLM 任务：判断整体新闻情绪方向、识别重大事件风险（监管/安全漏洞/宏观公告）、评估短期价格影响
  • 预处理：计算 avg_sentiment（所有新闻情绪分的均值），汇总标题与标签
  • 输出格式：OPINION / CONFIDENCE / RISK_FLAG / REASONING / KEY_POINTS

角色3宏观分析 (macro)

  • 输入：macro_events、latest_factors 中的 macro_* / market_cap / volume_24h / dominance 因子
  • LLM 任务：判断宏观环境是否支持风险资产、评估流动性与整体市场情绪、识别系统性风险
  • 输出格式：OPINION / CONFIDENCE / RISK_FLAG / REASONING / KEY_POINTS

角色4风控分析 (risk)

  • 输入：latest_factors 中的 ATR / volatility / RSI / drawdown / VaR / Sharpe、recent_signals 的置信度分布
  • LLM 任务：评估波动性水平、建议仓位与杠杆、ATR 止损距离、是否触发否决
  • 输出格式：OPINION: long/short/wait / CONFIDENCE / RISK_FLAG / REASONING / KEY_POINTS
  • 否决逻辑：risk_flag=true 且 confidence ≥ 0.7 -> 触发 risk_veto

四、多空辩论实现说明

Round 1: Bull View (多头论点)
  - 输入：context_summary（标的/价格/因子/角色摘要）+ role_opinions
  - 输出：从技术面/情绪面/宏观面最大程度论证做多理由，反驳潜在空头风险点

Round 2: Bear View (空头论点)
  - 输入：context_summary + bull_view（前一轮输出）
  - 输出：从阻力位/超买/背离/风险角度论证做空或观望，逐一反驳多头论点

Round 3: Final Judge (最终裁决)
  - 输入：context_summary + bull_view + bear_view
  - 输出：FINAL_ACTION (BUY/SELL/WAIT) / CONFIDENCE / DECISION_REASONING
  - 多空双方论据对比后做出最终交易方向判断

fast_mode=true 时跳过辩论，直接使用角色投票结果（4 次 LLM 调用 vs 7 次）

十一、接口约定

与叶同学（L1-L5 / AnalysisContext 输入）的接口约定

  • 输入方式：CoordinatorAgent 通过 AnalysisContextBuilder.build(symbol, interval) 获取上下文，不自行查原始数据。
  • 必需字段：bars（OHLCV K 线）、latest_factors（技术/新闻/宏观因子）、recent_signals（策略信号）、news_events（新闻情绪/标签）、macro_events（宏观指标）。
  • 审计字段：input_snapshot_ids（factor_snapshot_ids / signal_event_ids / news_payload_ids / macro_keys）透传到 coordination_history。
  • 兼容性：各字段为空列表/空字典时，四角色正常回退到默认判断（不报错）。
  • 格式约定：symbol 使用无斜杠格式（BTCUSDT），interval 使用标准周期（1h / 1d）。

与汪旭学姐（coordination_history 输出 / 前端消费）的接口约定

  • 输出方式：coordination_history 表包含完整 17 字段；API /coordination/latest、/coordination/history、/coordination/{id} 返回对应 JSON。
  • 决策字段：final_signal (BUY/SELL/WAIT) / confidence (0.0-1.0) / risk_veto (bool)。
  • 展示字段：bull_view / bear_view（多空论点全文）、role_opinions（四角色结构化输出数组）、summary（最终摘要）。
  • 风控字段：risk_notes（风险提示文本）、position_advice（{suggested_position_pct, max_leverage, stop_loss_pct, risk_suggestion, leverage_suggestion}）。
  • 审计字段：input_snapshot_ids（可回链到因子/信号/新闻/宏观快照）、vote_breakdown（看多/看空/中性权重）。
  • 扩展原则：如需新增字段，优先追加到 JSONB 或新增列，避免修改现有字段名称和类型。
